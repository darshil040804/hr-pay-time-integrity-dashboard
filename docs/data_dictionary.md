# Data Dictionary

> **All data is synthetic and fictional.** The tables are modeled on SAP HCM structures (Organizational Management, Personnel Administration, Time Management, Payroll). They do not come from a real SAP system or a real organization. Names are generated by Faker. "Example University" is fictional.

The dataset is produced by [`data/generate.py`](../data/generate.py) with a fixed seed (42), so every run produces identical CSV files. Column names and types are defined once in [`src/schema.py`](../src/schema.py).

## Conventions

| Convention | Meaning |
|---|---|
| Dates | `YYYY-MM-DD`. |
| `9999-12-31` | Open-ended end date: the record is valid until further notice (SAP convention). |
| Blank cell | Missing value (NULL). |
| Reporting window | 6 biweekly pay periods, 2026-01-05 to 2026-03-29. |
| As-of date | The end date of the last pay period (2026-03-29). Used by rules that ask whether something is "past" a date. |

## Overview

| Table | Rows | SAP equivalent | Description |
|---|---:|---|---|
| `org_units` | 40 | OM object type O (Organizational Unit) | University org hierarchy: 1 root, 5 divisions, 34 departments. |
| `jobs` | 18 | OM object type C (Job) | Generic job titles with FLSA status. |
| `positions` | 535 | OM object type S (Position) | Seats in an org unit, each linked to a job. |
| `employees` | 500 | PA infotypes 0001, 0002, 0007, 0000 | One row per person: assignment, grouping, schedule, employment status. |
| `wage_types` | 5 | Wage type catalog (table T512W) | Pay components. Codes are fictional. |
| `pay_periods` | 6 | Payroll period table (T549Q) | Biweekly periods and pay dates. |
| `time_entries` | ~29,600 | Time infotypes 2001 (Absences) / 2002 (Attendances), CATS | Hours recorded per employee per workday. |
| `payroll_results` | ~5,200 | Payroll results table RT | Paid hours and amounts per employee, period, wage type. |
| `planted_defects` | 11 | (none) | Expected exception count per rule. Single source of truth for tests. |

## `org_units`
Similar to SAP OM organizational units (object type O, infotype 1000/1001).

| Column | Type | Description |
|---|---|---|
| `org_unit_id` | string | Unique ID, e.g. `ORG014`. |
| `name` | string | Org unit name, e.g. "Payroll Office". |
| `parent_org_unit_id` | string | The org unit one level up. Blank for the root (`ORG001`). |
| `valid_from` | date | Start of validity. |
| `valid_to` | date | End of validity (`9999-12-31` = open). |

## `jobs`
Similar to SAP OM jobs (object type C).

| Column | Type | Description |
|---|---|---|
| `job_id` | string | Unique ID, e.g. `JOB06`. |
| `title` | string | Job title, e.g. "Payroll Specialist". |
| `flsa_status` | string | `Exempt` or `Non-exempt` under the US Fair Labor Standards Act. Non-exempt jobs are eligible for overtime. |

## `positions`
Similar to SAP OM positions (object type S) with relationships to an org unit (A003) and a job (A007).

| Column | Type | Description |
|---|---|---|
| `position_id` | string | Unique ID, e.g. `POS0123`. |
| `org_unit_id` | string | Org unit the position belongs to. Must exist in `org_units`. |
| `job_id` | string | Job the position is based on. Determines FLSA status. |
| `status` | string | `Active` (open for use) or `Inactive` (closed). |
| `valid_from` | date | Start of validity. |
| `valid_to` | date | End of validity (`9999-12-31` for active positions). |

A position is **vacant** when it is `Active` and no `Active` employee holds it. The clean data has 40 vacant and 20 inactive (closed) positions.

## `employees`
Combines what SAP stores in PA infotypes 0000 (Actions/status), 0001 (Organizational Assignment), 0002 (Personal Data), and 0007 (Planned Working Time).

| Column | Type | Description | SAP equivalent |
|---|---|---|---|
| `emp_id` | int | Unique employee number, 100001–100500. | Personnel number (PERNR) |
| `first_name` | string | Fictional first name. | IT0002 |
| `last_name` | string | Fictional last name. | IT0002 |
| `position_id` | string | Position held. Blank for terminated employees (SAP moves them to a default position, 99999999). | IT0001 PLANS |
| `employee_group` | string | `Faculty`, `Support Staff`, or `Temporary`. | IT0001 PERSG |
| `employee_subgroup` | string | `Salaried` or `Hourly`. Should match the job's FLSA status: Exempt → Salaried, Non-exempt → Hourly. | IT0001 PERSK |
| `weekly_scheduled_hours` | float | Planned weekly hours (20, 30, or 40). | IT0007 |
| `status` | string | `Active` or `Terminated`. | IT0000 employment status |
| `hire_date` | date | Hire date. | IT0000 hiring action |
| `term_date` | date | Termination date. Blank for active employees. | IT0000 termination action |

All 25 terminated employees left between July and December 2025, before the first pay period, so in clean data they have no time entries and no pay.

## `wage_types`
Similar to the SAP wage type catalog. Codes are fictional.

| Column | Type | Description |
|---|---|---|
| `wage_type` | string | 4-character code. |
| `description` | string | What the wage type pays for. |
| `eligible_flsa` | string | Who may receive it: `Both` or `Non-exempt`. |

| Code | Description | Eligible | Fed by attendance type |
|---|---|---|---|
| 1000 | Regular Pay | Both | Regular |
| 1100 | Overtime Pay (1.5× rate) | Non-exempt | Overtime |
| 1200 | Vacation Pay | Both | Vacation |
| 1300 | Sick Pay | Both | Sick |
| 1400 | Shift Differential ($1.50/hour premium) | Non-exempt | (none: premium on regular hours) |

**Shift differential (1400)** is a premium paid *on top of* regular hours that are already paid under 1000. Its hours are therefore **not** counted when paid hours are reconciled against recorded time (rule TP-01).

## `pay_periods`
Similar to SAP payroll periods for a biweekly payroll area.

| Column | Type | Description |
|---|---|---|
| `period_id` | string | `PP01` to `PP06`. |
| `start_date` | date | First day (a Monday). |
| `end_date` | date | Last day (a Sunday, 13 days later). |
| `pay_date` | date | Payday: the Friday after the period ends. |

## `time_entries`
Similar to SAP time infotypes 2001 (Absences) and 2002 (Attendances), or CATS time sheets.

| Column | Type | Description |
|---|---|---|
| `emp_id` | int | Employee. |
| `work_date` | date | Day worked or absent (weekdays only in clean data). |
| `hours` | float | Hours for that day and attendance type. Clean data: daily scheduled hours (weekly ÷ 5), or 1–3 for overtime. |
| `attendance_type` | string | `Regular`, `Overtime`, `Vacation`, or `Sick`. |

Every active employee, salaried or hourly, records time for every scheduled workday. Only non-exempt employees record overtime. An overtime entry is a separate row on the same day as a regular entry.

## `payroll_results`
Similar to the SAP payroll results table (RT). One row per employee, period, and wage type.

| Column | Type | Description |
|---|---|---|
| `period_id` | string | Pay period. |
| `emp_id` | int | Employee. |
| `wage_type` | string | Wage type code. |
| `hours` | float | Hours paid. |
| `amount` | float | Dollars paid (hours × the employee's hourly rate; × 1.5 for overtime). |
| `payment_date` | date | Date paid (the period's `pay_date`). |

In clean data, the paid hours for wage types 1000–1300 equal the recorded hours of the matching attendance type in that period. Each (employee, period, wage type) appears once.

## `planted_defects`

| Column | Type | Description |
|---|---|---|
| `rule_id` | string | Validation rule ID (matches `sql/<rule_id>.sql`). |
| `expected_count` | int | Number of exception rows the rule must return on the committed data. |

## Planted defects

The generator builds clean data first (every rule returns zero), then plants these defects in `plant_defects()`. Each defect uses employees and positions that no other defect touches, so each one trips exactly one rule.

| Rule | Check | Planted | How it is planted |
|---|---|---:|---|
| OP-01 | Active employee in an inactive position | 6 | 6 occupied positions are set to Inactive. |
| OP-02 | Position with missing or nonexistent org unit | 4 | 2 vacant positions get a blank org unit, 2 get `ORG999`. One row per position. |
| OP-03 | Two active employees in the same position | 3 pairs | 3 employees are moved into another employee's position (same subgroup). One row per extra employee. |
| OP-04 | Terminated employee still in an active position | 5 | 5 terminated employees are assigned a vacant position. |
| OP-05 | Subgroup inconsistent with job FLSA status | 5 | 3 Hourly employees marked Salaried, 2 Salaried marked Hourly. |
| TP-01 | Paid vs recorded hours differ by more than 0.5 in a period | 8 | Regular paid hours changed by ±1 to ±8. One row per employee per period. Excludes wage type 1400. Only compares employee-periods that have both time and pay (pay without time is TP-03). |
| TP-02 | Overtime (1100) paid to an Exempt employee | 4 | 4 exempt employees get a 4-hour overtime entry and matching 1100 pay line. |
| TP-03 | Active hourly employee paid with no time entries in the period | 5 | One period of time entries deleted; pay kept. One row per employee per period. |
| TP-04 | Time entry over 16 hours or negative | 6 | 3 entries set to 18/20/24 hours, 3 to −2/−4/−8. Pay was adjusted to match, so they don't also show as TP-01. |
| TP-05 | Duplicate payroll line (same employee, period, wage type) | 4 | 2 exact duplicates of a 1400 line, 2 regular-pay lines split into two halves. One row per duplicated combination. |
| TP-06 | Payment dated after the employee's term date | 3 | 3 terminated employees get a regular-pay line in 2026. |
