# HR Pay & Time Integrity Dashboard

**Live app:** _add the Streamlit Community Cloud URL here after deploying_

A Streamlit dashboard that validates and reconciles HR data before payday. It finds employees in closed positions, overtime paid to exempt staff, hours paid that were never recorded, duplicate pay lines, payments after termination, and more. Each problem comes with a plain-English explanation and a suggested fix.

> **All data is synthetic and fictional, modeled on SAP HCM structures** (Organizational Management, Personnel Administration, Time Management, Payroll). It does not use a real SAP system, real employee data, or data from any real organization. Names are randomly generated by Faker; any resemblance to real people is coincidental.

## What it shows

- **11 validation rules**, each a short, readable SQL file run by DuckDB: 5 org & personnel checks (OM/PA) and 6 time & payroll checks.
- **A dashboard** with severity-ranked exception lists, filters, Excel export, recorded-vs-paid hours by pay period, and HR KPIs (headcount, vacancy rate, exception rate).
- **Proof the rules work.** The dataset has exactly 53 planted defects. Tests check that every rule finds exactly its planted count, finds nothing in clean data, and handles boundaries correctly.
- **AI-assisted testing with a human in the loop.** An AI proposes tricky edge cases; a person reviews each one; only accepted cases become tests. *AI proposes, a human reviews, deterministic tests decide.*

| Rule | Check | Severity |
|---|---|---|
| OP-01 | Employee assigned to an inactive position | Medium |
| OP-02 | Position with missing or nonexistent org unit | Low |
| OP-03 | Two active employees in the same position | Medium |
| OP-04 | Terminated employee still assigned to an active position | High |
| OP-05 | Employee subgroup inconsistent with job FLSA status | High |
| TP-01 | Paid hours differ from recorded hours by more than 0.5 in a period | High |
| TP-02 | Overtime paid to an Exempt employee | High |
| TP-03 | Active hourly employee paid with no time entries in the period | Medium |
| TP-04 | Daily hours over 16 or negative | Medium |
| TP-05 | Duplicate payroll line (same employee, period, wage type) | High |
| TP-06 | Payment dated after the employee's term date | High |

## Run it locally

Requires Python 3.11.

```bash
git clone https://github.com/darshil040804/hr-pay-time-integrity-dashboard.git
cd hr-pay-time-integrity-dashboard
python -m venv .venv
.venv\Scripts\activate          # Windows
# source .venv/bin/activate     # macOS / Linux
pip install -r requirements.txt
streamlit run app.py
```

The app reads the committed CSVs in `data/`. It needs no API key and makes no AI calls.

To regenerate the data (identical output every time, seed 42):

```bash
python -m data.generate
```

## Run the tests

```bash
pytest
```

| Test file | What it checks |
|---|---|
| `tests/test_rules.py` | Each rule finds exactly its planted defects; zero exceptions on clean data; boundary checks |
| `tests/test_scenarios.py` | The 22 documented scenarios, including real dashboard runs with filters applied |
| `tests/test_ai_edge_cases.py` | AI-proposed edge cases a human has **accepted** (skipped until some are accepted) |
| `tests/test_ai_client.py` | AI client helpers (offline) |

Tests never call an AI API, so they run offline and give the same result every time.

## AI-assisted testing

The AI scripts in `ai/` run only on a developer's machine, never in the deployed app. They work with any OpenAI-compatible endpoint; this project uses Groq.

**Setup**
1. Get a free API key at [console.groq.com](https://console.groq.com).
2. Copy `.env.example` to `.env` and paste your key into `.env`. `.env` is gitignored, so never commit it.
3. Set `AI_MODEL` to a model your key can use. The committed cases were generated with `openai/gpt-oss-120b`.
4. Check the connection with `python -m ai.client`.

**Review workflow**
1. **Generate:** `python -m ai.generate_edge_cases`. The AI proposes 3–5 boundary cases per rule. Each is validated against the schema and saved to `tests/ai_generated/edge_cases.json` as `pending`.
2. **Dry run:** `python -m ai.generate_edge_cases --dry-run`. This runs the pending cases against the rules with no AI calls and prints `AGREE` or `DISAGREE`.
3. **Decide each disagreement:**
   - **The rule is wrong:** fix the SQL, open a GitHub Issue, mark the case `accepted` with `"rule_bug": true`.
   - **The AI is wrong:** mark the case `rejected` and explain why in `reviewer_note`.
4. **Accept sensible AGREE cases.** Only accepted cases run in pytest.
5. **Log** each disagreement in [docs/ai_testing_log.md](docs/ai_testing_log.md).

`python -m ai.draft_test_scenarios` drafts test scenarios for human editing ([draft](docs/test_scenarios_ai_draft.md) → [final](docs/test_scenarios.md)).

**Why only synthetic data is sent:** free-tier AI providers may use prompts to train their models. Only rule descriptions, SQL, table schemas, and made-up rows are ever sent, never real employee data.

## Deploy to Streamlit Community Cloud

1. Push the repo to GitHub (public).
2. At [share.streamlit.io](https://share.streamlit.io), create an app from the repo with main file `app.py`. Under **Advanced settings**, choose Python 3.11.
3. No secrets are needed.

## Project structure

```
app.py                     Home page (Streamlit entry point)
pages/                     Org & Personnel, Time & Payroll, HR Overview, Testing & QA, About
data/generate.py           Synthetic data generator with planted defects (seed 42)
data/*.csv                 Generated data and planted_defects.csv (expected counts)
sql/<RULE_ID>.sql          One validation rule per file
src/schema.py              Every table's columns and types, defined once
src/rules.py               Loads tables into DuckDB and runs the rules
src/dashboard.py           Shared page helpers: caching, Excel export, chart styling
src/edge_cases.py          AI edge-case format, validation, and runner
ai/                        Development-time AI scripts (client, edge cases, scenario draft)
tests/                     pytest suites and tests/ai_generated/edge_cases.json
docs/                      FDS, user guide, test scenarios, AI testing log, data dictionary
```
